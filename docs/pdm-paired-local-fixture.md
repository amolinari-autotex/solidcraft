# Private paired local evaluation

`paired_fixture` is an explicit native example for connecting a separately owned
CAD client to the transactional server. It changes no document RPC or admin API.
It is not remote enrollment or a production credential export feature.

Build with `cargo build --profile ci -p solidcraft-pdm-admin --example paired_fixture
-p solidcraft-pdm --bin solidcraft-pdm`.

1. Run `paired_fixture prepare NEW_ABSOLUTE_ROOT`. The parent must exist. An existing
   root, symlink or Windows reparse path fails closed. The existing console service
   creates the new private installation before writing TLS data, enrolls a random
   administrator, imports the store into redb and creates a contributor through the
   real admin API. The roles are `paired-admin` / administrator and `paired-author`
   / contributor. It stops its owned server before returning.
2. Read `paired-descriptor.json` in that root. Version 1 contains `origin`,
   `server_id`, `certificate_der_path`, `deployment_config` and `accounts`. Each
   account contains `principal_id`, `role` and `bearer_path`. No bearer appears in
   the descriptor or standard output. Each private bearer file has exactly 64
   lowercase hexadecimal bytes without a newline, generated by OS entropy.
3. Start the owned `solidcraft-pdm rehearse-https DEPLOYMENT_CONFIG` child with its
   standard input retained by the launcher. It emits one public readiness JSON
   line with `server_id` and `address`. Verify both against the descriptor. The
   fixed loopback port fails closed if occupied; never select an alternate port
   while silently reusing the old credential scope.
4. The client installer reads the explicitly selected private bearer file,
   authenticates using the exact origin, original DER certificate and pinned
   server identity, verifies the returned principal, then captures the credential
   through its existing native credential boundary. Settings and empty client
   working folders are separate for each identity and separate from the physical
   server installation. Never print, commit or publicly distribute bearer files.
5. Send `shutdown` and a newline, or close this exact child's standard input, then
   wait for it. Restart with the same deployment configuration and original
   identity. Do not stop processes by name or control an existing user trial.

The Windows root ACL disables inheritance and grants only the current account and
SYSTEM; Unix uses 0700/0600. Static path checks do not protect against a malicious
owning OS account changing files concurrently. TLS keys, bearer files and redb
metadata are private. Copying the binary package does not copy the fixture.

`paired_fixture proof OWNED_FIXTURE_ROOT` mutates only a separately prepared toy
installation. It exercises real pinned HTTPS with both identities, contributor
admin denial, exclusive checkout, checkout persistence across restart, part v1/v2,
an assembly pinned to part v1, history, exact old bytes, Where Used and another
restart. It prints a success line only after stopping the final owned server.
The byte payloads are plain toy text, not CAD validation. The paired native client
owner separately verifies actual CAD files and its UI/adapters.

The example deliberately uses an in-memory capture adapter and then retains two
private local bearer files for the explicit client handoff. It does not provision
the regular console's OS credential slot; do not expect this fixture to reopen in
that console without a separate native enrollment. Failures preserve the partial
new installation; no existing archive is reset, repaired or migrated implicitly.
No public/LAN listener, cloud account, tunnel, firewall change or persistent system
service is created. Existing draft PRs remain draft pending human trial review.
